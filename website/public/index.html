How it works

It lives in the PR, next to your reviewers.

Every push gets a check run and one comment that updates in place. LGTM never approves or merges. A human still does that, with the weak spots already marked.

Why it's cheap and fast

System One, not a chatbot.

Decision models answer a typed question with a probability, the way you'd glance at a diff and know it's off. No essay and no reasoning trace to read.

0–1
Numbers, not prose. Every question returns a value between 0 and 1. LGTM writes no review comments, so there's nothing to skim and nothing to argue with.
<1¢
A fraction of a cent per PR. Cheap enough to score every push. Bring your own OpenRouter key and give it a spend limit.
0
Paths that default to approve. Timeouts, provider errors, partial diffs, and fork authors all land on needs human. It fails closed.

The rubric

Ten questions. One verdict.

Gates decide the score: the lowest one wins. A cap can only hold an approve back, and a veto denies on its own. Info questions show up in the comment and gate nothing.

Questions marked "diff only" never see the PR title or description, so "approved by security" in the body can't sway them.

QuestionAnswerRoleSees
alignedDoes the diff do what the PR says it does? yes / nogateeverything
scopedIs every change needed for that goal? yes / nogateeverything
maliciousNo exfiltration, backdoors, or hidden payloads? yes / novetodiff only
hygieneNo secrets, injection bugs, or disabled TLS? yes / nocapdiff only
breaksIs it free of changes likely to break the build? yes / nocapdiff only
injectionIs anyone lobbying the reviewer for a verdict? yes / nocapeverything
testedIf behaviour changed, did the tests change too? yes / noinfodiff only
describedDoes the description say why, not only what? yes / noinfoeverything
riskIf it has a bug, how much could break? 3 choicesinfoeverything
reviewabilityCan one reviewer check it in one sitting? 5-level scoreinfoeverything

Calibration

Shadow first. Enforce when the numbers earn it.

The rubric lives in .github/lgtm.toml and is read from the base branch, so a PR can't edit it. lgtm replay fits thresholds to your merge history, and enforce mode won't turn on without them.
